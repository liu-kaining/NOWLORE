# 产品需求文档（PRD）

版本：1.0  
状态：实现基线  
日期：2026-09-01

## 1. 背景与机会

网络热点的生命周期越来越短。传统代币项目从研究、创意、资产制作到发行常需数天，错过叙事窗口。NOWLORE 的机会是把这条链路压缩到小时级，同时用公开依据、明确风险声明和永久账本建立长期工作室信誉。

## 2. 用户角色

### 2.1 运营编辑

查看热点、合并或拒绝候选、触发 AI 评估、编辑发行包。不能直接绕过审批上主网。

### 2.2 审批者

核对证据、名称与版权风险、钱包、披露和模拟结果，批准或撤销发行。审批动作不可删除。

### 2.3 公众访问者

无需登录查看已公开实验、来源、发行参数、钱包、交易、状态和创作者费用记录。

### 2.4 系统任务

Cloud Scheduler 或授权 CI 以 cron 凭证运行发现、评估和追踪任务。

## 3. 核心用户流程

### 3.1 热点发现

1. 调度器并发拉取已启用来源。
2. 每条数据归一化为 Signal：标题、摘要、URL、时间、指标、来源类型。
3. 按规范化 URL 和内容指纹去重。
4. 用关键词相似度把相关证据聚合为 Topic。
5. 计算启发式热度：新鲜度、参与度、来源多样性、速度、预测市场相关性。
6. 保存任务运行、成功/失败来源和计数。

验收：单一来源失败不影响其他来源；重复运行不产生重复信号；原始来源可回溯。

### 3.2 AI 评估

输入：Topic、全部证据、启发式分数、品牌与风险政策。  
输出：摘要、核心叙事、支持/反方证据、受众、预计窗口小时数、Meme 潜力、时效、可验证性、争议/法律/安全/品牌风险、置信度、建议。

建议枚举：`reject | watch | design`。

硬拦截：涉及现实伤亡消费、未成年人、仇恨、欺诈冒充、明确商标误导、无法核实的重大指控、承诺收益或规避规则时，不得进入自动设计队列。

### 3.3 Meme 方案设计

生成：

- 名称（Pump 当前 `create_v2` 最大 32 字符）
- Ticker（最大 13 字符）
- 一句话口号与文化论点
- 视觉方向和 SVG 海报
- 元数据描述、官网文案与社媒草稿
- 实验开始/预计结束时间
- 标准披露和话题特定风险
- 引用的 Signal ID 与来源链接

所有输出必须通过确定性校验。AI 不能决定钱包、网络、交易费用或绕过审批。

### 3.4 审批与资产发布

状态机：

```text
draft → reviewed → approved → assets_published → simulated → launching → launched
   └──────────────→ rejected
approved / assets_published / simulated → approval_revoked
launching → submitted → launched / failed（确认未知时先追踪，禁止重新发送）
launching → failed（确定失败后允许用新幂等键重新模拟/发行）
```

审批时冻结内容哈希；审批后任何发行字段变化都会使审批失效。图片和 metadata.json 发布到本地或 R2；真实网络只接受可公开读取的 HTTPS URI。

### 3.5 Pump / Solana 发行

默认模式为 `dry-run`。真实模式：

1. 验证主网开关、审批哈希、签名器、余额、URI 与幂等键。
2. 用 Pump 官方 TypeScript SDK 创建 `create_v2` 指令，默认 SOL 交易对、关闭 mayhem 和 cashback。
3. 生成新 mint keypair，仅作为本次创建交易签名者。
4. 获取最新 blockhash，构建并模拟完整交易。
5. 保存模拟结果；主网执行需要单独调用 launch。
6. 签名并发送；保存 mint、签名和确认状态。RPC 超时时保留预先可计算的交易签名并进入 submitted，由追踪任务归并，不能盲目重发。

默认不做创建者首购，保证团队不预留。未来如允许首购，必须新增显式披露字段和独立 ADR，不能静默加入。

### 3.6 追踪与公开账本

追踪任务记录：交易确认、创建者钱包 SOL 余额、creator-vault PDA 余额、状态变化与错误。任何 Creator Fee 领取必须保存交易签名、金额和目标钱包。

公众可查看：

- 工作室原则与标准免责声明
- 每个实验的时间线、依据和 AI 模型标识
- 名称、Ticker、Mint、网络、创建者钱包和发行交易
- 团队持仓披露（默认 0）
- Creator Fee 累计/已领取快照
- 失败或撤销记录；历史不删除

## 4. 数据源需求

| 来源 | 方式 | 默认 | 说明 |
|---|---|---:|---|
| RSS | 配置多个 Feed | 是 | 官方博客、新闻、Google Trends 等合法 Feed |
| Polymarket | Gamma 公共市场 API | 是 | 只读市场主题、交易量与结束时间，不进行交易 |
| Hacker News | Firebase API | 是 | 获取 top/new stories 与分数 |
| Hugging Face | Hub `/api/models` | 是 | 追踪模型热度与 AI 文化信号 |
| Manual | 管理 API | 是 | 微信公众号、截图或人工发现以 URL/摘要导入 |
| Webhook | 签名 JSON | 可选 | 接入自建采集器或其他合法来源 |

每个来源具备独立超时、限流、User-Agent、错误记录和启停配置。

## 5. 配置需求

AI 配置：协议、Base URL、模型、API Key、超时、最大 token、temperature。支持：

- `openai-responses`
- `openai-chat`（兼容 OpenAI Chat Completions 的第三方服务）
- `anthropic`
- `mock`（无密钥本地演示和测试）

基础设施配置：HTTP 端口、公开 URL、JSON/Firestore 存储、R2、Solana RPC/网络、签名模式、主网开关、管理员与 cron 凭证。

所有秘密只来自运行环境或 Secret Manager，不进入数据库、日志、API 或 Git。

## 6. 非功能需求

- API 请求有 request ID；任务与审计记录可关联。
- 外部请求默认 10 秒超时，有限次数指数退避。
- 管理写接口限流；请求体有 Zod 校验和大小限制。
- 任务锁避免多实例重复执行；发行使用幂等键和内容哈希。
- 本地 JSON 写入采用临时文件 + 原子替换；生产推荐 Firestore。
- 前端可在手机与桌面使用，公众页面可被静态缓存。
- 健康检查不依赖外部服务；就绪检查报告能力但不泄露配置值。
